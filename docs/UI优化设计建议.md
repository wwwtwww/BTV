# BTV 界面与视觉系统（UI/UX）全景优化建议书

> 本文档针对 BTV 客户端的大屏交互与视觉表现进行系统性梳理，遵循 **10-foot Leanback** 电视交互体验标准（参考 YouTube TV、Apple TV tvOS 17 与 Material 3 for TV），并严密覆盖 **深色（Dark）与浅色（Light）双主题系统**，为后续 UI 体验迭代提供清晰的技术与设计指引。

---

## 1. 总体设计原则

| 维度 | 设计基准 | 核心原则 |
|---|---|---|
| **视距标准** | 10-foot（约 3 ~ 4 米视距） | 远距离一眼可辨，字重与对比度必须充足 |
| **操控介质** | 遥控器 D-Pad 方向键为主 | 强调焦点的物理存在感与移动反馈流畅度 |
| **双主题兼顾** | 深色（夜间/沉浸）+ 浅色（日间高亮客厅） | 深浅两套色彩配方，禁止全仓硬编码暗黑或纯白 |
| **显示载体** | 大尺寸 4K / 1080P OLED / Mini-LED / LCD 电视 | 深色极致纯黑防漏光，浅色冷瓷柔光防刺眼 |
| **交互核心** | 沉浸式与直达性 | 减少厚重弹窗遮挡，选集与设置轻量化悬浮 |

## 2. 四大维度优化建议

> **说明**：本章中标注 **✅ 已于 P0/P1 落地** 的条目已全面实施并合入主线（详见 [第 4 章各阶段工作量评估与任务拆解](#4-各阶段工作量评估与任务拆解)）；标注 **⏳ 转入 P2 待办** 的高级布局条目改动范围广，已完整归档至 [TODO.md](../TODO.md) 待分批立项。

### 一、UI 布局优化（大屏视线流动与沉浸感，⏳ 转入 P2 待办）

#### 1. 首页：引入「沉浸式 Hero 动态海报看板（Showcase Banner）」（⏳ 待办 P2-3）
- **现状分析**：当前首页顶部直接展开 Filter Chips 胶囊和横向卡片泳道，整体排版较为紧密，但缺少大屏电视独有的“视觉焦点”。
- **改进方案**：
  - 在精选页顶部设立全屏宽幅的 **Hero Showcase** 动态高光区；
  - 遥控器焦点移入任意视频卡片并停留 400ms 后，背景自动平滑渐变透出该视频的高清封面、剧照截帧、动态大字标题、UP 主、播放统计与简介；
  - 提供大尺寸「立即起播」与「进入详情」快捷操作，营造家庭影院级的沉浸观感；
  - *(详细实现方案与架构设计已归档至 [TODO.md#3-首页-hero-showcase-沉浸看板](../TODO.md#3-首页-hero-showcase-沉浸看板))*。

#### 2. 播放器：将左侧厚重选集面板升级为「底部横向胶囊选集轨」（⏳ 待办 P2-2）
- **现状分析**：目前在播放视频时呼出分集列表（`VideoListController`），是从屏幕左侧滑入一个宽达 300dp 的竖向遮罩面板，遮挡了将近 1/3 的画面内容。
- **改进方案**：
  - 采用轻量级**下推式交互**；
  - 播放中按遥控器「上」或「下」方向键，仅在屏幕底部展开一条水平滑动的**分 P / 集数胶囊微轨**；
  - 附带微型缩略图与分集标题，当前播放集自动高亮居中；选集切换时主画面几乎不被遮挡；
  - *(详细实现方案与架构设计已归档至 [TODO.md#2-播放器底部横向胶囊选集轨](../TODO.md#2-播放器底部横向胶囊选集轨))*。

#### 3. 搜索页：重塑左右栏比例与键盘自适应（⏳ 待办 P2-1）
- **现状分析**：目前搜索页左栏固定放置全字母软键盘，横向占用宽度过大（约 40%），导致右侧搜索结果卡片的展示空间被挤压，视频卡片偏小且文字拥挤。
- **改进方案**：
  - 优化左栏占宽至约 28% ~ 30%，引入「T9 九宫格拼音简拼」或紧凑型键盘；
  - 右侧视频结果网格扩展为 3 列宽幅卡片，提供更大的封面面积与更舒展的元数据展示空间；
  - *(详细实现方案与架构设计已归档至 [TODO.md#1-搜索页紧凑键盘与宽网格3-列卡片](../TODO.md#1-搜索页紧凑键盘与宽网格3-列卡片))*。

### 二、菜单与文本排版（10-foot 远距可读性标准，✅ 已于 P0 落地）

#### 1. 字重提升与字距调校（Tracking & Weight，✅ 已于 P0 落地）
- **现状分析**：原先大量辅助信息直接采用 `bodySmall` 或 `labelSmall` 的 Regular 字重，在低色域或大尺寸电视上面板发虚，远距离阅读易产生疲劳。
- **实施方案**（已合入 `core/theme/Typography.kt`）：
  - **核心元数据（UP 主名称、播放量、弹幕数）**：由 Regular 统一提升为 **Medium（500）**；
  - **核心标题（视频名、卡片标题）**：统一采用 **SemiBold（600）~ Bold（700）**；
  - **字距微调**：英文与数字在等宽/时间码场景（通过 `tabular()` 与 `timecode`）微调字距 `letterSpacing = 0.5.sp`，中文保持自然舒展，大幅提升远距离瞬间扫读舒适度。

#### 2. 时间码与数值等宽对齐（Tabular Figures，✅ 已于 P0 落地）
- **现状分析**：原先播放器下方的实时播放时间（如 `01:23 / 45:10`）和倍速浮动提示在时间跳动时，因非等宽字符导致数字宽度频繁微变，产生微弱的水平视觉抖动。
- **实施方案**（已合入 `ControllerVideoInfo.kt`、`LiveControllerInfo.kt`、`SmallVideoCard.kt`、`LiveRoomCard.kt` 等组件）：
  - 为播放时间码、弹幕数量、视频时长引入等宽字体特性（`FontFeatureSettings("tnum")`，Tabular Numbers）；
  - 彻底消除数字跳动时的水平排版抖动。

### 三、色彩体系与双主题适配（深色 Dark 与浅色 Light，✅ 已于 P0/P1 落地）

BTV 设置项支持「跟随系统 / 深色模式 / 浅色模式」，色彩体系已全面兼顾黑白双主题，杜绝硬编码颜色。

#### 1. 深浅双主题设计配方对照表（✅ 已于 P0 落地）

| 设计维度 | 深色主题（Dark Mode） | 浅色主题（Light Mode） | 架构实现约束 |
|---|---|---|---|
| **背景底色（Background）** | **True OLED 微蓝黑**<br>`#090D16` ~ `#0C101A`<br>（高对比、通透、暗场纯黑） | **雅致冷瓷白 / 雾面灰**<br>`#F4F6FA`<br>（杜绝纯白 `#FFFFFF` 导致大屏过曝刺眼） | 禁止硬编码 `Color.Black`，由 `MaterialTheme.colorScheme.background` 派生 |
| **卡片/容器（Surface）** | **深空微透黑**<br>`rgba(255, 255, 255, 0.05)`<br>微弱磨砂质感 | **纯白悬浮面板**<br>`#FFFFFF`<br>与冷瓷白底形成轻量对比悬浮 | 绑定 `MaterialTheme.colorScheme.surface` |
| **前景色阶（文字）** | **纯白不透明阶梯**<br>• 一级：`#FFFFFF` (100%)<br>• 二级：`rgba(255,255,255,0.75)`<br>• 三级：`rgba(255,255,255,0.50)` | **深靛/石板灰阶梯**<br>• 一级标题：`#111827` (近黑 100%)<br>• 二级正文：`#4B5563` (石板灰 75%)<br>• 三级弱文本：`#9CA3AF` (冷灰 50%) | 禁止硬编码 `Color.White`，统一使用 `onSurface` / `onSurfaceVariant` |
| **焦点获焦反馈 (Focus)** | **极光高光边框与物理放大**<br>1.06x 放大 + 高光对比边框 | **环境深靛边框与物理放大**<br>1.06x 放大 + 品牌色加粗外框 | 生产组件全量接入 `TvFocusDefaults.cardScale()` / `cardBorder()`；实验性 Glow/Shadow 引擎封装于 `tvFocusFeedback()` 待按需启用 |
| **播放器全屏沉浸特例** | **默认深色** | **强制/嵌套深色**（全屏观影时 OSD 防刺眼暗场） | 播放器外围遵从全局，但全屏播放界面内部固定包裹 `BVTheme(ThemeMode.Dark)` |

#### 2. 深色模式细节：OLED 深度幽蓝黑与极光流光（✅ 已于 P0/P1 落地）
- 根背景采用深度幽蓝黑（`#090D16` ~ `#0C101A`），在 OLED 面板上黑色像素彻底关闭，通透纯粹且大幅省电；
- 获焦态引入 B 站标志性的 **电光青（#00F5FF）与柔光粉（#FA5383）** 作为点睛呼吸光晕。

#### 3. 浅色模式细节：冷瓷雅致白与立体微投影（✅ 已于 P0/P1 落地）
- 根背景避免使用刺眼的 `#FFFFFF` 纯白大反光，采用低反光冷瓷灰白 `#F4F6FA`；
- 内容卡片与悬浮抽屉使用纯白 `#FFFFFF`，在底色之上自然形成层次分明的悬浮卡片；
- 获焦态通过弥散阴影（Drop Shadow）与品牌色（`#5E5A8B`）边框锁定焦点位置。

### 四、边框形状与焦点质感（Shape Tokens 与三维反馈，✅ 已于 P0/P1 落地）

#### 1. 建立全局统一的 Shape Tokens（终结圆角碎片化，✅ 已于 P0 落地）
- **现状分析**：原先全仓圆角值高度分散（存在 `3.dp`、`4.dp`、`8.dp`、`10.dp`、`12.dp`、`16.dp`、`18.dp`、`20.dp`、`50%` 等多达十几种定义），视觉缺乏统一律动感。
- **实施方案**（已收敛并确立四大标准 Shape Tokens，黑白主题完全通用，合入 `core/theme/BVTheme.kt`）：

| Token 名称 | 圆角规格 | 适用场景 |
|---|---|---|
| `Shape.Small` | `8.dp` | 微型标签（Tag）、清晰度角标、时间指示微标 |
| `Shape.Medium` | `12.dp` | 功能按钮、抽屉导航项、菜单列表行、设置项 |
| `Shape.Large` | `16.dp` | 视频卡片、弹窗对话框、功能浮层卡片 |
| `Shape.Pill` | `50%`（全圆角胶囊） | 筛选胶囊（Filter Chips）、快捷按键圆形徽章 |

#### 2. 从「平面单线框」进化为「三维立体双态焦点体系」（⚠️ 边框与缩放已落地，Glow/Shadow 作为能力储备）
- **现状分析**：原先卡片获焦主要依赖描边 `border(2.dp, PrimaryLight)`，属于扁平化反馈，远距离操作时缺乏立体感。
- **实施方案**：
  1. **生产组件已全量落地**（`SmallVideoCard`、`SeasonCard`、`LiveRoomCard`、`UpCard` 等）：
     - **物理放大（Scale）**：统一绑定 `TvFocusDefaults.cardScale()`，获焦平滑放大至 1.06x；
     - **自适应高对比边框**：深色模式使用高光边框 `colorScheme.border`，浅色模式使用深靛品牌色边框 `BVColors.PrimaryStrong`（`TvFocusDefaults.cardBorder()`）；
  2. **实验性能力储备**：
     - 极光发光（Ambient Glow）与悬浮投影（Drop Shadow）引擎已封装于 `core/focus/TvFocusFeedback.kt`（`Modifier.tvFocusFeedback`）；因 TV 端 LazyRow 容器边界裁剪（Clipping）及低端电视芯片硬件开销，生产卡片暂未直接启用，后续视大屏容器重构进度按需接入。

* **P0 基石规范（Shape + 字体 + 双色板）**：约 **2 ~ 3 人天**（已完成并发布 v0.3.0）。
* **P1 交互与质感（卡片缩放与自适应边框）**：约 **2 ~ 2.5 人天**（核心缩放与边框已全量落地，氛围发光/投影作为底层能力储备）。
