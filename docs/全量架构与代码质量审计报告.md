## 一、总结（Executive Summary）

本次审计从 **架构与设计规范、逻辑正确性与并发安全、大屏 TV 交互与性能、代码与注释规范、测试覆盖与质量** 五大维度对 BTV 展开全量静态扫描与逐文件审查（当前仓库 `./gradlew detekt` 与 `./gradlew ktlintCheck` 静态检查均通过）。

### 架构与工程亮点
1. **单 Activity 与类型安全路由落地彻底**：全应用严格保持 [`MainActivity.kt`](../app/src/main/kotlin/dev/frost819/newbv/app/MainActivity.kt) 单 Activity 架构，[`Routes.kt`](../app/src/main/kotlin/dev/frost819/newbv/app/ui/navigation/Routes.kt) 与 [`AppNavHost.kt`](../app/src/main/kotlin/dev/frost819/newbv/app/ui/navigation/AppNavHost.kt) 100% 采用 `@Serializable` 类型安全路由，全仓零字符串拼接路由。
2. **焦点安全基础设施**：全仓 UI 组件已全面采用 [`.safeRequestFocus()`](../core/src/main/kotlin/dev/frost819/newbv/core/focus/FocusExt.kt#L35-L45)，无一处裸调 `.requestFocus()`；模态弹窗主体均采用独立窗口 `Dialog` 隔离焦点。
3. **技术栈收敛清晰**：彻底移除了原版 BV 的 Koin、VLC 与 Firebase，完成了 Media3 点播/直播统一封装与多模块职责拆分。

### 核心风险画像
深入并发边界、生命周期交界与 TV 焦点细节后，暴露出 **12 类阻断级严重隐患（🔴）**，集中体现在：
- **安全与隐私合规**：扫码登录明文 `println` 打印 `SESSDATA`/`access_token` 到 Logcat、生产环境信任用户 CA 证书并全局放行明文流量、退出登录未清理 `BiliHttpApi` 内存登录态、用户锁旧密码验证完全失效。
- **低版本崩溃与资源泄漏**：直接调用 API 28/24 方法导致 `minSdk 21` 设备必崩；每次进直播间创建两个 `ExoPlayer` 永久泄漏后台线程与 `Activity`；`Prefs` 三个全局 `StateFlow` 写成 `get()` 导致每次重组永久泄漏协程。
- **结构化并发与跨页污染**：`handleGrpcException` 与 28+ 处 `runCatching` 吞掉 `CancellationException`；退出播放页末次进度上报被 `onCleared()` 同一帧取消；详情页/UP 空间/账号切换存在跨实体数据污染。
- **TV 大屏焦点与帧率**：[`FocusSaver`](../app/src/main/kotlin/dev/frost819/newbv/app/ui/component/FocusSaver.kt#L83-L97) 存在每次移动焦点延迟抢焦与重试失效两大核心缺陷；播放器控制器因顶层解包 `seekerState.value` 产生 10Hz 全树重组；弹幕蒙版在主线程同步解码 SVG/Bitmap。

### 示例 1：修复 `FocusSaver.kt` 每次移动焦点延迟抢焦与返回重试失效（对应 **C-10**）
文件：[`FocusSaver.kt`](../app/src/main/kotlin/dev/frost819/newbv/app/ui/component/FocusSaver.kt#L77-L105)

```kotlin
/**
 * 仅在进入/返回当前组合树时恢复一次焦点到先前保存的 key，失败时回退至 [fallbackRequester]。
 *
 * 修复点：
 * 1. 使用 `LaunchedEffect(Unit)` 替代 `LaunchedEffect(savedKey.value)`，避免页面内移动焦点时反复触发抢焦；
 * 2. 在每次 `delay` 循环内动态查询 `requesters[key]`，等待 LazyRow/LazyGrid 子项首帧组合挂载。
 */
@Composable
fun RestoreFocus(
    fallbackRequester: FocusRequester? = null,
    maxRetries: Int = 5,
    retryDelayMs: Long = 60L,
) {
    LaunchedEffect(Unit) {
        val key = savedKey.value
        if (key.isNotEmpty()) {
            // 先立即尝试一次（已挂载同步组件零延迟恢复）
            if (requesters[key]?.safeRequestFocus() == true) return@LaunchedEffect
            repeat(maxRetries) {
                kotlinx.coroutines.delay(retryDelayMs)
                if (requesters[key]?.safeRequestFocus() == true) {
                    return@LaunchedEffect
                }
            }
        }
        if (fallbackRequester != null) {
            kotlinx.coroutines.delay(retryDelayMs)
            fallbackRequester.safeRequestFocus()
        }
    }
}
```

### 示例 2：修复直播双 `ExoPlayer` 线程/Activity 泄漏与 `BEHIND_LIVE_WINDOW` 死锁（对应 **C-04、C-05**）
文件：[`ExoMediaPlayer.kt`](../player/src/main/kotlin/dev/frost819/newbv/player/impl/exo/ExoMediaPlayer.kt#L84-L126) 与 [`LivePlayerViewModel.kt`](../app/src/main/kotlin/dev/frost819/newbv/app/viewmodel/live/LivePlayerViewModel.kt#L131-L181)

```kotlin
// 1. ExoMediaPlayer.kt：强制使用 applicationContext，重建前先彻底释放旧实例，并修复防抖早退死锁
class ExoMediaPlayer(
    context: Context,
    private val options: VideoPlayerOptions,
) : AbstractMediaPlayer(), Player.Listener {
    private val appContext: Context = context.applicationContext
    private val mainHandler = Handler(Looper.getMainLooper())
    private var pendingLiveRecoverRunnable: Runnable? = null

    override fun initPlayer() {
        // 防止重复调用 initPlayer() 泄漏旧 ExoPlayer 后台 Playback 线程
        mPlayer?.removeListener(this)
        mPlayer?.release()

        val renderersFactory = buildRenderersFactory(appContext)
        mPlayer =
            ExoPlayer.Builder(appContext)
                .setRenderersFactory(renderersFactory)
                .setSeekForwardIncrementMs(10_000L)
                .setSeekBackIncrementMs(5_000L)
                .build()
                .also { it.addListener(this) }
    }

    override fun release() {
        pendingLiveRecoverRunnable?.let(mainHandler::removeCallbacks)
        pendingLiveRecoverRunnable = null
        mPlayer?.removeListener(this)
        mPlayer?.release()
        mPlayer = null
        mMediaSource = null
        mPlayerEventListener = null
    }

    private fun tryRecoverBehindLiveWindow(error: PlaybackException): Boolean {
        val player = mPlayer ?: return false
        if (behindLiveWindowRecoverAttempt >= 2) return false // 超过阈值交由外层上报 onError

        val nowMs = SystemClock.elapsedRealtime()
        val elapsed = nowMs - behindLiveWindowLastRecoverAtMs
        if (elapsed < BEHIND_LIVE_WINDOW_RECOVER_MIN_INTERVAL_MS) {
            // 绝不可直接 return 将 STATE_IDLE 播放器悬空丢弃，延迟补做恢复
            if (pendingLiveRecoverRunnable == null) {
                val delayMs = BEHIND_LIVE_WINDOW_RECOVER_MIN_INTERVAL_MS - elapsed
                pendingLiveRecoverRunnable = Runnable {
                    pendingLiveRecoverRunnable = null
                    if (!tryRecoverBehindLiveWindow(error)) {
                        mPlayerEventListener?.onError(error)
                    }
                }.also { mainHandler.postDelayed(it, delayMs) }
            }
            return true
        }
        behindLiveWindowLastRecoverAtMs = nowMs
        behindLiveWindowRecoverAttempt += 1
        if (behindLiveWindowRecoverAttempt == 1) {
            player.seekToDefaultPosition()
            player.prepare()
            player.playWhenReady = true
            return true
        }
        val source = mMediaSource ?: return false
        player.setMediaSource(source, /* resetPosition = */ true)
        player.prepare()
        player.playWhenReady = true
        return true
    }
}
```

```kotlin
inline fun <R> runSuspendCatching(block: () -> R): Result<R> =
    try {
        Result.success(block())
    } catch (t: TimeoutCancellationException) {
        Result.failure(t)
    } catch (c: CancellationException) {
        throw c
    } catch (t: Throwable) {
        Result.failure(t)
    }
```
